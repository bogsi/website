# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Personal/consulting site for roussev.dev: a **Hugo** static site on the `terminal` theme (git submodule at `themes/terminal`, from panr/hugo-theme-terminal), plus one **Cloudflare Pages Function** for the inquiry form. Deployed by Cloudflare Pages' Git integration: every push to `main` deploys production, and PR branches get preview deployments.

Site config is `hugo.toml`.

## Commands

```bash
git submodule update --init      # fetch the theme if themes/terminal is empty
hugo server -D                   # dev server at http://localhost:1313 (includes drafts)
hugo --minify                    # production build into public/ (gitignored)
```

The Hugo site has no tests, linter or JS build (`package.json` at the root is an npm stub). To verify a site change, run `hugo --minify` and confirm it finishes with no errors, because template `errorf` calls are used as build-time assertions (see below). Code under `admin/`, `functions/` and `lib/` is tested from `admin/` (`npm test`, `npx tsc -b`, `npm run build`).

## Architecture

- **Layouts override the theme.** Files in `layouts/` take precedence over `themes/terminal/layouts/`. `layouts/_default/baseof.html` and `layouts/partials/head.html` replace the theme's shell entirely. `head.html` bundles `assets/css/style.css` through Hugo Pipes, defines the orange accent CSS variables inline, and does not load any analytics: GA4 runs through Cloudflare Zaraz, which injects itself at the edge and loads GA4 only after consent (the footer's "Cookie settings" link reopens the Zaraz modal and mirrors the choice to Google Consent Mode v2). `resources.Get` reads `assets/` (project and theme), never `static/`. Each section (`about`, `services`, `projects`, `posts`, `order`) has its own `list.html`.
- **Service pages drive several places through front matter.** A page in `content/services/` can set:
  - `service_summary`: rendered by `layouts/partials/service-card.html`. The `service-pane` shortcode (`layouts/shortcodes/service-pane.html`) embeds that card in a YAML-highlighted box on `content/services/_index.md`. Both **fail the build** (`errorf`) if the referenced page is missing (for example, still `draft: true` in a production build) or has no `service_summary`.
  - `inquiry_service`: automatically added as an `<option>` in the inquiry form (`layouts/order/list.html`). The form also preselects a service from `?service=<value>`, so links like `/order/?service=CostLens%20AWS%20Cost%20Audit` must match that value exactly.
- **Inquiry flow:** the form in `layouts/order/list.html` POSTs JSON to `/api/order`, which is handled by `functions/api/order.js` (Cloudflare Pages Functions file-based routing; there is no `_routes.json`, so Cloudflare generates routes automatically. If you add one, it must go in `static/` to be deployed, and it must keep `/api/*` included). The function drops submissions that fill the hidden `website` honeypot, verifies the Cloudflare Turnstile token server-side (`siteverify`; 10 s timeout; it must match action `order` and a hostname in `TURNSTILE_HOSTNAMES`, a comma-separated allowlist where `*.example.com` matches subdomains; the function fails closed with 503 if `TURNSTILE_SECRET_KEY` or `TURNSTILE_HOSTNAMES` is unset; a rejected token returns 403 whose message ends with a reason code such as `invalid-input-secret` or `hostname-not-allowed`), validates and length-limits the input, stores the order and its two emails in D1 (`DB` binding, database `roussev-orders`, schema in `admin/migrations/`, emails via `lib/outbox.js`; anti-relay: the customer confirmation repeats no visitor text and goes to one address at most `CLIENT_CONFIRMATIONS_PER_DAY` (2) times in 24 hours, after which only the admin email is sent and a note is added to the order), then sends both emails through Resend in `waitUntil` with every visitor value HTML-escaped (an email failure is non-fatal; the outbox retries). D1 is the only store: without the `DB` binding the function returns 503 before any other work. It returns `{success, orderId}`, and the form script then redirects to `/order/success/?id=ORD-…`. Environment variables are set in Cloudflare: `RESEND_API_KEY`, `FROM_EMAIL`, `ADMIN_EMAIL`, `TURNSTILE_SECRET_KEY`, `TURNSTILE_HOSTNAMES` (production: `roussev.dev`; never `localhost`). The public site key is `params.turnstileSiteKey` in `hugo.toml`; the build fails (`errorf`) while it is empty. The Turnstile widget needs `https://challenges.cloudflare.com` in `script-src` and `frame-src` of the CSP in `static/_headers`. CORS is pinned to `https://roussev.dev`, so the function can't be tested end to end from `hugo server`.
- **Admin dashboard (`admin/`)**, separate from the Hugo build: one Cloudflare Worker at `admin.roussev.dev` serving a Vite/React SPA as static assets plus a Hono API under `/api` (only `/api/*` invokes the Worker). Cloudflare Access (GitHub login) guards the hostname and `src/api/access.ts` re-verifies the Access JWT on every request; `workers_dev` and preview URLs are off. Every status change emails the client (`src/api/email.ts`). All emails, from the form and the dashboard, go through `lib/outbox.js`: queued in `email_outbox` in the same D1 batch, sent, and retried by the admin Worker's hourly cron (max 5 attempts); `orders.notify_status` summarises delivery. Commands run inside `admin/`: `npm test` (vitest; D1 emulated by better-sqlite3, also covers `functions/api/order.js`), `npm run build`, `npx wrangler dev`. `.github/workflows/admin.yml` tests PRs; on `main` it runs `admin/scripts/provision.ts`, which idempotently creates D1, the Access GitHub login, policy and app, deploys the Worker, sets the Resend secret and binds `DB` to the Pages project. `wrangler.jsonc` keeps `REPLACE_` placeholders that the script fills into a gitignored `wrangler.ci.jsonc`. Manual setup (4 steps), the one-off import of old Google Sheet orders (CSV), backups and key rotation are in `admin/README.md`.
- **SEO plumbing:** `layouts/partials/head.html` emits the meta description (`.Description`, falling back to `params.description`) and `robots` `noindex` for tag/category pages and any page with `noindex: true` in its front matter. `<title>` is rendered only in `baseof.html`. `layouts/partials/structured-data.html` builds the JSON-LD graph: Person and ProfessionalService on every page (profile URLs come from `params.social`), BlogPosting for posts and projects, Service for service pages with `service_summary`, and BreadcrumbList. `layouts/_default/sitemap.xml` leaves out noindexed and taxonomy pages, and `layouts/robots.txt` adds the `Sitemap:` line. Give every new content page a `description` of 120–160 characters. `params.images` sets the default social preview (`static/images/og-default.png`, 1200×630) for Hugo's OpenGraph and Twitter templates, so a page's own `images` front matter overrides it. In `layouts/_default/single.html`, the byline links the author (falling back to `params.author`) to `/about/`, and `layouts/partials/article-cta.html` adds a CostLens/inquiry call to action to every post and project. Set `hide_cta: true` on an article that already ends with its own.
- **Security headers / CSP** live in `static/_headers`. The CSP only allows scripts from `'self'` plus inline scripts, styles/fonts from cdnjs (Font Awesome) and `cdn.staticdelivr.com` (Fira Code, the only web font), and fetches to `'self'` and `api.rss2json.com` (the Medium feed on the posts list). Any new external script, font or fetch target must be added there or it will be blocked in production.
- **Static downloads:** `static/downloads/costlens/` holds client-facing CostLens files (kit ZIP and a read-only IAM CloudFormation template). Per README, these are byte-verified copies from a signed private CostLens release. Refresh them only from a verified release. Never add the private CLI, workspace files or keys.
- `static/tools/dbm-mw-converter/` is a standalone HTML tool linked from the projects section.
- `archetypes/projects.md` is the front-matter template for `hugo new projects/<name>.md`.

## CI

Cloudflare Pages builds and deploys the site; no workflow builds Hugo. Every action is pinned to a commit SHA (Dependabot updates the pins), and workflows default to `permissions: contents: read`.

- `admin.yml`: on PRs touching `admin/`, `functions/` or `lib/`: `npm audit --audit-level=high`, vitest, tsc, build. On `main`: `provision.ts deploy` (see Architecture).
- `d1-backup.yml`: Sundays and on demand, `age`-encrypted D1 export as a 30-day artifact (recipient in `admin/backup/recipients.txt`).
- `zone-hardening.yml`: manual, with a short-lived `CLOUDFLARE_ZONE_TOKEN`: DNSSEC, TLS, the `/api/order` rate limit, WAF custom rules, and read-only Access and email DNS reports.
- `smoke-test.yml`: daily read-only checks of production (headers, form, WAF rules, admin behind Access, security.txt expiry).
- `rotation-reminder.yml`: quarterly issue with the key rotation checklist.
- `claude-code-review.yml` / `claude.yml`: Claude review on PRs and `@claude` mentions, for the owner and collaborators only (skipped for Dependabot, which gets no secrets).

Each change goes on its own branch and pull request; the owner merges. Security reports: `SECURITY.md`.
